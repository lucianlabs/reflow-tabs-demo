↘ Drag the frame's bottom right corner, or use the width slider below, to resize it and watch tabs collapse into "More".

Keyboard Shortcuts:

  • ← → switch tabs
  • Home End first / last tab
  • ↑ ↓ on More opens the menu
  • ↑ ↓ in the menu move between items
  • Enter choose the focused item
  • Esc close the menu

    Overview

    This section summarizes the project's current state at a glance: overall health, the milestones coming up next, and anything that needs attention before the next release window. Treat it as the first stop for anyone joining the project partway through, since every other tab drills into one slice of what's outlined here.

    Updates roll in from the team's day-to-day work across activity, analytics, and files, so this overview is regenerated automatically rather than maintained by hand. If something here looks stale, check the Activity tab for the most recent raw events.

    Activity

    A running log of what's changed recently: commits, comments, status updates, and anything else the team has touched. Entries are grouped by day and sorted newest first, so the most relevant context always surfaces at the top without needing to scroll.

    Filtering by person or by section is available from the toolbar above the feed (not shown in this demo). Older entries are paginated rather than infinitely loaded, which keeps the panel's height predictable even on projects with a long history.

    Analytics

    Traffic, engagement, and conversion trends for the project, broken down by week and by source. The charts here favor trend lines over raw totals, since the day-to-day noise matters less than whether a metric is moving in the right direction over time.

    Export options include CSV and a shareable snapshot link, so numbers can be pulled into an external report without giving someone full access to this dashboard. Historical data further back than 12 months is archived separately.

    Team

    Everyone with access to this project, along with their role and how recently they've been active. Owners can adjust permissions directly from this list; everyone else can see roles but not change them.

    Pending invitations show up here too, greyed out until they're accepted. Removing someone from the team revokes their access immediately but leaves their past contributions (commits, comments, uploaded files) attributed to them.

    Files

    Shared documents, exports, and uploaded assets for the project, organized into folders that mirror the project's own structure. Anyone on the team can upload; deleting a file moves it to a recoverable trash for 30 days before it's permanently removed.

    Large files are versioned automatically, so overwriting a document doesn't lose the previous copy. Search covers file names and, for common document types, the text inside them.

    Files example link

    Integrations

    Connections between this project and outside tools: chat notifications, issue trackers, deployment pipelines, and anything else that needs to react to changes here. Each integration can be scoped to specific event types instead of firing on everything.

    Disconnecting an integration stops new events immediately but doesn't undo anything it already triggered. Some integrations require re-authorizing periodically depending on the third party's own token expiry policy.

    Settings

    Project-level configuration: name, visibility, default branch or workspace, and the notification preferences that apply to everyone unless they override them individually. Changes here take effect immediately for all members.

    Dangerous actions -- archiving, transferring ownership, or deleting the project outright -- live in a separate section further down and require typing the project name to confirm, to make them harder to trigger by accident.

    Billing

    Current plan, seat usage, and the next billing date, along with a history of past invoices available for download. Usage-based charges (storage overages, extra build minutes) are itemized separately from the flat subscription fee.

    Payment method and billing contact can be updated by anyone with owner access. Downgrading a plan takes effect at the end of the current billing cycle rather than immediately, so there's no prorated refund to account for.
